# Comunicação de problemas

Para conteúdo editorial, abra uma issue no repositório público de distribuição com o identificador da questão e a versão. Não inclua credenciais, dados pessoais sensíveis ou material confidencial do exame.

Para uma vulnerabilidade de segurança do aplicativo, evite publicar detalhes exploráveis com dados reais. Use o canal privado oferecido pelo GitHub quando estiver habilitado ou o contato profissional do criador para coordenar o encaminhamento.

O aplicativo não pede senha, cadastro ou credenciais. Os dados de progresso ficam no navegador e em backups exportados pelo próprio usuário.
